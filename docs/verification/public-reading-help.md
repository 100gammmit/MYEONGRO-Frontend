# FAQ·사용 가이드 검증 기록

## 목적과 범위

- 비로그인 FAQ 12문항, 타로·사주 가이드를 분리한다. FAQ 문항은 실제 문의 빈도 자료가 아닌 현재 기능에서 예상되는 질문이다.
- 말투는 종결어미 통일보다 자연스러움과 정확성을 우선한다. 정책·처리 기준에는 명료한 합니다체를 쓴다.
- 애드센스 승인 보장, 광고 코드, 신규 AI API·DB·CMS, 운영 프롬프트 변경은 범위 밖이다.
- 기존 `/about/reading`은 계산·AI 해석 원리를 설명하는 역할로 유지한다.

## AI-preview 실제 호출

- 실행일: 2026-10-30 (Asia/Seoul).
- 기존 로컬 secret 설정을 사용했다. 키를 출력·복사·변경하지 않았다.
- Backend 기준 HEAD: `1ba7812d221d963624a54fd91c6dc967b1a94f9b`. 다른 작업의 미커밋 변경이 있는 작업 트리에서 실행했다. 생성기 변경은 진단 정보 수집 호출, application 설정 변경은 재시도·타임아웃·생성 제한이며, 프롬프트 변경은 없었다. 해당 변경을 수정하거나 커밋하지 않았다.
- 모델: `gpt-6-luna`. 타로 3개 유형과 사주 4개 관심 분야에서 짧은 질문/맥락을 보완한 질문을 각각 1회, 총 14회 호출했다. 전부 생성기 검증을 통과했다.
- 같은 비교 쌍에서는 카드·자리·정역방향 또는 사주 계산정보·연도·관심 분야를 고정했다. 실행별 prompt SHA-256도 일치한다.
- 입력은 모두 가상 데이터다. 사주는 합성된 최소 계산정보를 사용했으며 실제 생년월일이나 사용자 데이터는 사용하지 않았다.
- Preview는 운영 Controller·입력 정규화를 거치지 않는다. 이 검증은 질문의 맥락 활용을 관찰하는 것으로, 명식 계산 정확성·운영 E2E·예측 정확성 평가가 아니다.
- 쌍마다 한 번의 생성이므로 확률적 변동과 입력 변경의 효과를 분리한 통계 실험이 아니다. 개선율·정확도 점수나 보편적 우월성 주장은 하지 않는다.

### 관찰과 콘텐츠 반영

| 비교 | 실제 관찰 | 가이드에 반영한 범위 |
| --- | --- | --- |
| 타로 고민 | 짧은 질문에서는 불확실함과 실행의 일반론, 맥락 보완에서는 업무 범위 조율·착수·한 달의 전개를 다뤘다. | 어떤 일인지와 궁금한 범위를 적는다. 기간은 사건·날짜 보장이 아니다. |
| 타로 관계 | 연락 간격과 이유를 모른다는 맥락을 주면 연락 공백과 실제 대화의 차이를 다뤘다. | 관찰한 사실과 모르는 이유를 구분한다. 타인의 속마음이 확인된 것으로 읽지 않는다. |
| 타로 선택 | 동일 카드에서도 짧은 질문은 혼자 공부, 미루는 습관을 더한 질문은 스터디 쪽으로 권고가 바뀌었다. | 두 선택과 현실 조건을 명확히 한다. 권고 변화는 정확도 향상의 증거가 아니다. |
| 사주 성향 | 일반적인 자기 기준 설명에서 자료 수집과 실행 지연의 연결로 질문 해설이 구체화됐다. | 관찰한 행동을 맥락으로 제공하되 자기평가가 사주로 입증됐다고 여기지 않는다. |
| 사주 일·진로 | 일반적인 성과 표현에서 기존 업무를 익히는 일과 새 역할 경험을 연결했다. | 지금 고민하는 방향을 명시한다. 직장명 등 개인정보는 필요하지 않다. |
| 사주 관계 | 일반적인 관계 확대에서 새 모임·친해지는 속도 맥락으로 구체화됐다. 한편 원국 관계 설명에도 자기보고가 섞여 강화되는 모습이 있었다. | 어떤 관계가 궁금한지 설명하되 이를 고정 성격·확정 사실로 보증하지 않는다. |
| 사주 생활·돈 | 일반적인 돈의 흐름에서 반복되는 소액 지출에 초점을 맞췄다. 특정 수익·손실은 단정하지 않았다. | 생활 맥락을 적되 투자·재정 판단을 대신하지 않는다고 안내한다. |

입력에 없는 특정 날짜·실명·사건을 확인된 사실로 만들어내는 사례는 이번 표본에서 발견하지 못했다. 다만 상징 해석과 자기보고를 결합한 성향 설명은 검증된 사실이 아니다. 짧은 질문도 답변이 생성됐으므로 길이·특정 표현을 필수 조건으로 만들지 않는다. 프롬프트는 변경하지 않았으며 사주 자기보고와 원국 해석의 구분은 후속 품질 평가 대상으로 남긴다.

### 재현 자료

- `public-reading-help-preview.json`에 14개 합성 입력과 실행별 모델·프롬프트 hash·소요 시간·요약을 보관한다. 자동 생성 답변은 공개 페이지에 그대로 게시하지 않았다.
- Backend의 ignored 경로 `src/aiPreview/resources/ai-preview/cases/<kind>/<id>.json`에 해당 fixture를 놓고 실행한다.
- 명령: `.\gradlew.bat aiPreview -Pkind=<kind> -Pcase=<id> -Pexecute=true --console=plain`.
- 전체 결과: Backend `build/ai-preview/<label>/<kind>-<caseId>.json` 및 `.md` (ignored 로컬 산출물).
- 타로 카드 수와 canonical position, choiceOptions, 사주 focusArea/targetYear/evidence key를 운영 코드와 대조했다. 사주 fixture는 시간 기둥 미확정인 최소 정보이며, 오행 수는 제시된 여섯 글자 기준이다.

## 화면·회귀 검증

- `src/components/reading-help.test.tsx`: SSR 본문, 12문항, FAQ 직접 링크·잘못된 hash, 가이드 목차, 교차 앵커, 메타데이터, 새 탭 링크.
- 기존 타로·사주 컴포넌트 테스트: 새 탭 도움말과 질문·출생정보 유지.
- 기존 홈 테스트: 새 안내 영역의 순서.
- 브라우저 체크: 서버 실행 후 `node scripts/check-reading-help.mjs`. 기본 URL `http://localhost:3105`, 브라우저 Chrome. `HELP_BASE_URL`·`HELP_BROWSER_CHANNEL`로 로컬 환경 지정 가능.
- 브라우저 산출물은 `build/reading-help-check/`에 저장하며 커밋하지 않는다.
- 브라우저에서 실제 AI 생성 또는 사용자 계정 로그인은 수행하지 않는다. 인증 입력 흐름은 기존 fixture 기반 컴포넌트 테스트로 확인한다.
- 관련 테스트 4 files / 79 tests 통과. 업데이트·공지 모델 관련 테스트 8개도 통과했다. 최초 홈 순서 assertion은 안내 영역 추가에 맞춰 갱신했다.
- 실제 Chrome headless에서 375px·1280px, 3개 페이지 HTTP 200·메타데이터·가로 넘침 없음, FAQ Enter/Space 조작·직접 링크·focus, 홈 진입과 새 탭 연결, JavaScript 비활성 본문·FAQ 조작을 확인했다. 모바일 FAQ와 데스크톱 타로 가이드의 캡처를 시각 검토했다.
- 최초 브라우저 실행의 localhost 접근은 sandbox에서 차단됐다. 허용된 실행 환경의 로컬 서버(127.0.0.1:3106)와 브라우저에서 동일 체크를 재실행해 통과했다.
- 마일스톤 전체 검증: `npm.cmd test` 74 files / 463 tests 통과, `npm.cmd run typecheck`, `npm.cmd run lint`, `npm.cmd run build` 통과. 전체 검증은 한 차례 실행했고, build 단계만 `.next/server/app/api` 생성 권한 EPERM 때문에 허용된 환경에서 재실행했다.
- 기존 전역 CSS의 autoprefixer `end` 경고와 기존 헤더 테스트의 jsdom navigation 경고가 있었으나 검증은 통과했다. 해당 무관한 코드는 변경하지 않았다.

## 운영상 경계

- 콘텐츠는 공개 열람용이며 새 개인정보 저장·전송 경로가 없다. 입력 화면의 도움말은 새 탭으로 열고 URL에 입력을 포함하지 않는다.
- 글로벌 레이아웃의 기존 세션 조회는 유지하므로 정적 본문이 곧 완전한 SSG 또는 Backend 무의존을 뜻하지 않는다.
- 개인정보 보유·국외이전의 정확한 정책은 `/privacy`와 기존 동의 문서를 기준으로 한다. FAQ는 요약이며 해당 문서를 대체하지 않는다.
- 오류 FAQ는 연결 오류와 생성 실패를 구분한다. 전송 결과가 불명확하면 기록 확인 후 화면 안내를 따르게 하며 무조건 새로운 생성 요청을 권하지 않는다.
- 일반 기능 업데이트 공지를 추가한다. 배포 날짜가 변경되면 미공개 상태에서 게시·시행일을 실제 배포에 맞춰 확인한다.
